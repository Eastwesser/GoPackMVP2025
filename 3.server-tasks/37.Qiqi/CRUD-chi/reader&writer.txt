В контексте горутин и синхронизации в Go, термины "читатель" (reader) и "писатель" (writer) относятся к типам доступа к общим данным:

Читатель (Reader)
Кто это: Горутина, которая только читает общие данные (не изменяет их).

Пример: Функция listUsers или getUser, которая читает из map users.

Как работает:

Использует RLock() (блокировка для чтения)

Много читателей могут работать одновременно

Блокируется, если есть активный писатель

usersMutex.RLock() // Захватываем блокировку для чтения
defer usersMutex.RUnlock()
// Читаем данные...

Писатель (Writer)
Кто это: Горутина, которая изменяет общие данные.

Пример: Функции createUser, updateUser, deleteUser.

Как работает:

Использует Lock() (эксклюзивная блокировка)

Только один писатель может работать в момент времени

Блокирует всех читателей и других писателей

usersMutex.Lock() // Захватываем эксклюзивную блокировку
defer usersMutex.Unlock()
// Изменяем данные...
Почему это важно?
Без синхронизации:

При одновременном доступе может возникнуть гонка данных (data race)

Возможны повреждения данных (особенно в map)

Аналогия с библиотекой
Читатели — как посетители библиотеки, которые могут одновременно читать книги

Писатель — как библиотекарь, который изменяет каталог. Пока он работает:

Новые читатели не допускаются

Другие библиотекари ждут своей очереди

Особенности sync.RWMutex
Приоритет:

Писатели имеют приоритет (новые читатели ждут, если есть ожидающий писатель)

Производительность:

RWMutex эффективнее обычного Mutex, когда много операций чтения

Методы:

RLock() / RUnlock() — для читателей

Lock() / Unlock() — для писателей

Пример из вашего кода

// Читатель (много может работать одновременно)
func listUsers(w http.ResponseWriter, r *http.Request) {
    usersMutex.RLock() // Захват для чтения
    defer usersMutex.RUnlock()
    // ... чтение данных ...
}

// Писатель (только один в момент времени)
func createUser(w http.ResponseWriter, r *http.Request) {
    usersMutex.Lock() // Эксклюзивный захват
    defer usersMutex.Unlock()
    // ... изменение данных ...
}

Когда что использовать?
RWMutex — когда у вас частое чтение и редкая запись (как в вашем API)

Обычный Mutex — если чтение и запись происходят с одинаковой частотой

Таким образом, разделение на читателей и писателей позволяет оптимизировать параллельный доступ к данным, минимизируя блокировки.
